# Уроки (Lessons Learned)

Файл ведётся с 2026-11-13 (UTC). Новые записи добавляются только в конец.
Существующие записи не удаляются и не переписываются.

## Постоянные правила (для всех задач)

- Не объявлять PASS без реального лога и файла результата.
- Не писать «готово», пока не проверено командой.
- Любая долгая команда: заданный таймаут, условие выхода и вывод прогресса в файл лога.
- После ошибки не повторять ту же команду более одного раза: сначала прочитать сообщение об ошибке и записать урок.
- Не менять и не удалять чужие файлы проекта. Только `audit/`. Перед заменой своего файла делать копию в `audit/backups/<UTC-время>/`.
- Если не уверен в версии, лицензии или параметре — проверить по первоисточнику, а не по памяти.
- Каждый ответ пользователю: что сделано, что проверено командой, что не проверено.

## Записи

### L1 — Цикл опроса без выхода при завершении (2026-11-13)
- Что произошло: для опроса Kaggle был запущен `for i in $(seq 1 18); do kaggle kernels status ...; sleep 30; done`. Статус `KernelWorkerStatus.COMPLETE` вернулся сразу (04:06:44), но цикл продолжал опрашивать до конца всех 18 повторов (до 04:13:57, около 7 минут впустую). Причина остановки — внешний таймаут команды (SIGTERM, exit 143).
- Причина: в цикле не было условия выхода по терминальному статусу; условие `grep` искало строку в другом формате (`status "complete"` вместо `KernelWorkerStatus.COMPLETE`).
- Последствие: ~7 минут лишнего ожидания, exit code 143 вместо нормального завершения.
- Правило на будущее: любой опрос статуса писать как цикл с выходом по терминальному статусу и предельным сроком. Образец:
  `end=$((SECONDS+1800)); while [ $SECONDS -lt $end ]; do s=$(kaggle kernels status <ID> 2>&1); echo "$(date -u +%T) $s"; case "$s" in *KernelWorkerStatus.COMPLETE*|*KernelWorkerStatus.ERROR*|*KernelWorkerStatus.CANCEL*) break;; esac; sleep 30; done`.
  Запрещены циклы фиксированной длины без условия выхода.
- Как проверять: в команде опроса есть `break` по терминальному статусу и предельный срок; в логе виден выход сразу после первого COMPLETE.

### L2 — COMPLETE не равно «результат получен и корректен» (2026-11-13)
- Что произошло: статус `KernelWorkerStatus.COMPLETE` означает только, что скрипт завершился на стороне Kaggle. Он не гарантирует наличие ожидаемых файлов, их размер, читаемость JSON и успешность проверок внутри скрипта.
- Причина: статус платформы и содержимое результата — разные вещи; сам скрипт может завершиться с внутренним FAIL/BLOCKED.
- Последствие: при доверии одному статусу возможен ложный PASS без лога и артефактов.
- Правило на будущее: после COMPLETE обязательно скачать результат (`kaggle kernels output <ID> -p <папка> -o`), проверить, что ожидаемые файлы существуют, имеют ненулевой размер и открываются, прочитать лог и внутренний summary. Только после этого писать PASS. Если файла или поля нет — BLOCKED или FAIL с указанием, чего именно нет.
- Как проверять: в отчёте для каждого PASS указан путь к скачанному файлу и фрагмент лога; JSON проходит `json.load` без ошибок.
### L3 — Неверный шаблон raw.githubusercontent URL (2026-11-13)
- Что произошло: в `collect_licenses.py` URL собирался как `https://raw.githubusercontent.com/{repo}/raw/{sha}/{file}`. Все 15 GitHub LICENSE были сохранены как MISSING (404). Ручная проверка `curl` показала, что корректный URL — `https://raw.githubusercontent.com/{repo}/{sha}/LICENSE` (HTTP 200, 1062 байта для hzwer/Practical-RIFE).
- Причина: лишний сегмент `/raw/` в шаблоне; шаблон не был проверен на одном компоненте до массового запуска.
- Последствие: повторный прогон сборщика лицензий и временно пустые `LICENSE-code.txt` в 15 компонентах.
- Правило на будущее: перед массовым сбором проверить шаблон URL на одном известном файле и убедиться в HTTP 200.
- Как проверять: `curl -sSL -o /dev/null -w '%{http_code}\n' '<url>'` возвращает 200 до запуска цикла по всем компонентам.

### L4 — Пробел в имени файла curl и HTML с ключами (2026-11-13)
- Что произошло: `curl -o "audit/provenance/kaggle_efficient_gpu_usage Wayback.html"` содержал пробел в имени выходного файла; HTML-код (20 КБ, с `<script>` и site key) был напечатан в stdout, файл не создан. Дополнительно выяснилось, что архивная копия `kaggle.com/docs/notebooks` — это SPA-оболочка без содержимого документации.
- Причина: имя файла с пробелом и без проверки результата; архив не содержит server-rendered текста.
- Последствие: лишний вывод в лог и риск попадания site key в коммит.
- Правило на будущее: имена файлов без пробелов; после скачивания проверять, что файл непустой и содержит ожидаемый текст; HTML с `<script>`/ключами не коммитить, удалять после извлечения текста.
- Как проверять: `test -s <file>` и `grep -c '<script' <file>`; при наличии скриптов файл удаляется до `git add`.

### L5 — `$?` после пайпа (2026-11-13)
- Что произошло: `git fetch --all --prune 2>&1 | tail -30; echo "FETCH_EXIT=$?"` — переменная `$?` содержала код завершения `tail`, а не `git fetch`.
- Причина: после конвейера `$?` относится к последней команде конвейера.
- Последствие: нельзя было утверждать, что fetch успешен; потребовался повторный запуск `git fetch` с проверкой кода.
- Правило на будущее: не проверять `$?` после пайпа; использовать `${PIPESTATUS[0]}` или перенаправление вывода в файл с последующей проверкой `$?`.
- Как проверять: `git fetch ... > /tmp/opencode/fetch.log 2>&1; echo "EXIT=$?"` возвращает реальный код git.

### L6 — Лицензия по полю model card не равна лицензии весов (2026-11-13)
- Что произошло: для CosyVoice 3, Kokoro, Whisper, Depth Anything V2, Video Depth Anything в model repo нет отдельного файла лицензии; лицензия известна только из поля `license:` model card.
- Причина: поле model card — это метаданные, а не текст лицензии на конкретный файл весов.
- Последствие: возможна выдача лицензии весов за подтверждённую без текста и без права на коммерческое использование.
- Правило на будущее: записывать `"license_basis": "model_card_metadata"` и статус `"условный PASS"` (conditional PASS), не считать это окончательным PASS; при наличии текста лицензии — статус PASS и путь к LICENSE-weights.txt.
- Как проверять: в audit/licenses/STATUS.json для таких компонентов есть license_basis=model_card_metadata и license_status="CONDITIONAL PASS"; для компонентов с текстом лицензии указан путь к файлу.
